# 草莓智农助手 MVP：产品与技术方案

## 目标与范围

在单一草莓合作社或设施园区中验证“问诊首轮分流、农事台账自动草稿、农技审核闭环”。首期服务 10–30 名用户、10–50 个棚室，周期 90 天。

系统聚焦：

1. 草莓叶片、果实、整株等照片/文字观察的保守初筛；
2. 中文语音转写或文字农事描述的结构化台账草稿；
3. 农技员审核、复查和本地案例沉淀。

不做自动灌溉/施药控制、最终病害诊断、农药处方或基础模型训练。

## 用户故事

| 角色 | 核心任务 |
|---|---|
| 种植户 | 上传问题照片、描述症状、确认农事记录 |
| 棚室管理员 | 管理棚室/批次、补充水肥和用工信息 |
| 农技员 | 审核高风险问题、给出结论与复查日期 |
| 负责人 | 查看风险工单和台账完成情况 |

- 用户上传“叶片白色粉状斑点”，系统提示白粉病风险、补拍叶背和检查通风。
- 用户输入“今天 A3 棚浇水八吨，冲施水溶肥二十公斤”，系统返回可编辑草稿。
- 农技员修订初筛结论，形成可追溯的已验证案例。

## API 概要

| 接口 | 用途 |
|---|---|
| `GET /health` | 健康检查 |
| `POST/GET /api/v1/farms` | 农场最小创建/列表 |
| `POST/GET /api/v1/plots` | 棚室最小创建/列表 |
| `POST/GET /api/v1/crop-cycles` | 种植批次最小创建/列表 |
| `POST /api/v1/observations` | 创建观察记录并返回规则化初筛 |
| `GET /api/v1/observations/{id}` | 查询观察及审核结果 |
| `POST /api/v1/observations/{id}/reviews` | 保存农技审核 |
| `POST /api/v1/farming-records/draft` | 创建农事台账草稿 |
| `POST /api/v1/farming-records/{draft_id}/confirm` | 确认并保存台账 |

## 数据模型

```text
Farm -> Plot -> CropCycle
CropCycle -> FarmingRecord -> FarmingInput
CropCycle -> CropObservation -> ExpertReview
AuditLog：关键创建、确认、审核动作
KnowledgeDocument：受控知识元数据
```

## 90 天路线图

- 第 1–2 周：锁定试点棚室，收集规程、50 个高频问题、100 张标注案例图；
- 第 3–4 周：完成基础实体、知识文档、图片引用与基础接口；
- 第 5–6 周：初筛规则、台账草稿、审核工作流；
- 第 7–8 周：10–30 人试点，收集专家修订和回访；
- 第 9–10 周：评测集、安全拦截、规则版本；
- 第 11–13 周：发布 1.0 并确定传感器、追溯或库存的扩展优先级。

## 验收指标

- 台账字段提取准确率 >= 85%；
- 首轮响应 <= 60 秒；
- 台账填写耗时降低 >= 50%；
- 高风险植保请求拦截率 = 100%；
- 每条初筛都有不确定性、下一步和来源/审核状态；
- 用户“有帮助”反馈 >= 80%。

## 上线要求

生产环境必须补齐登录与 RBAC、图片对象存储、加密与备份、知识/规则审批、模型调用审计、人工值守 SLA 和本地法规治理。
